# Использование AI

Журнал использования AI-инструментов при выполнении задания «EDA и машинное обучение» (вступительное испытание в
магистратуру ИТМО «Искусственный интеллект»).

Использование AI-ассистентов на испытании разрешено. Условие — честно раскрыть, где AI помог, что перепроверено
самостоятельно и какие решения приняты автором.

**Инструменты:** Claude Code (Opus 5).

## Как ведётся журнал

- Запись добавляется только для **содержательной** AI-помощи: анализ, код, выбор метрик, валидация, интерпретация
  результатов. Мелочи (чтение файлов, форматирование, переименования)
  не логируются.
- Промпты и полные диалоги не копируются — достаточно короткой сути.
- Ничего не выдумывается: если проверка не проводилась, это так и пишется.
- Формат — короткие пункты, 3–6 строк на запись.

Шаблон записи:

```markdown
### <этап / задача>

- **Помощь AI:** что именно предложил или сделал ассистент.
- **Проверено:** что проверил автор или что подтвердилось выполнением кода на данных
  (сверка чисел, размерностей, ручной пересчёт, контрольный пример).
- **Изменено / отклонено:** какие предложения AI не приняты и почему (если было).
- **Решения автора:** что выбрано самостоятельно (постановка, метрика, схема валидации,
  трактовка результата).
```

  сверки кода и документации.
- **Проверено:** содержание файлов прочитано и принято автором; требования к раскрытию использования AI сверены с
  официальным гайдом по подготовке и регламентом ВИ.
- **Решения автора:** состав окружения (Python 3.13, uv, src-layout, pandas/scikit-learn), язык документации для
  комиссии — русский, и решение не фиксировать заранее никаких предположений о типе ML-задачи и датасете.

### Настройка рабочего процесса под фактическое задание (до решения вопросов)

- **Помощь AI:** Claude Code переписал инструкции проекта `CLAUDE.md` под фактически полученное задание и выбранный

  протокол завершения каждого вопроса и правила обновления `AI_USAGE.md` / `README.md`.
- **Проверено:** локальные `TASK.md`, `README.md`, `AI_USAGE.md`, `pyproject.toml`, `.gitignore`, структура репозитория и
  наличие файлов в `data/` прочитаны перед правкой; DuckDB подтверждён в зависимостях `pyproject.toml`.
- **Изменено / отклонено:** из прежней версии `CLAUDE.md` убрано правило «не предполагать тип ML-задачи и модальность
  данных» — задание получено, тип задачи (бинарная классификация `relief_granted`) известен из `TASK.md`; вместо него

- **Решения автора:** порядок работы (по одному вопросу), приоритеты уровней (A и B обязательны, затем C, P — только по
  явному запросу), выбор DuckDB вместо Polars/Parquet-конвертации, запрет на изменение `TASK.md` и на коммиты/пуши без
  явного запроса, ноутбук как основной артефакт.

### A1 — Размерность обучающего датасета

- **Помощь AI:** Claude Code создал `notebooks/solution.ipynb` с общей setup-ячейкой (пути к данным, соединение DuckDB,
  выражения чтения CSV для переиспользования дальше) и посчитал размерность обучающего файла через DuckDB
  `read_csv(..., all_varchar=true, parallel=false)`; дополнительно оформил демонстрацию ловушки из условия — подсчёт
  физических переводов строк в файле — и независимую перепроверку другим парсером.
- **Проверено выполнением кода на данных:** результат `13 367 673` строки и `18` колонок получен двумя независимыми
  парсерами — DuckDB и `pyarrow.csv` с `newlines_in_values=True`; совпадение зафиксировано `assert` в ноутбуке. Наивный
  подсчёт переводов строк даёт `23 307 172` (завышение в 1.74 раза), что подтверждает предупреждение в условии о
  переносах строк внутри текстового поля. Список 18 колонок выведен полностью и сверен с заголовком CSV; таргет
  `relief_granted` присутствует. Отдельно установлено, что параллельный CSV-ридер DuckDB на этом файле падает с
  `Parallel CSV Reader currently does not support a full read on this file`, поэтому чтение идёт с `parallel=false`.
- **Изменено / отклонено:** первоначальная попытка прочитать файл параллельным ридером DuckDB отклонена по фактической
  ошибке, а не обходом через опции пропуска ошибок; вывод типов отключён (`all_varchar=true`), чтобы грязные значения и
  несколько форматов дат не искажали чтение. Из ноутбука убран виджет прогресса DuckDB, чтобы в сохранённых выводах
  оставались только содержательные результаты.
- **Решения автора:** формат ответа «строки; колонки» согласно условию; включение в ноутбук доказательства ловушки с
  переносами строк, а не только итогового числа.
