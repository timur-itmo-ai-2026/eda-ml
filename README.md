# eda-ml

Решение задания «EDA и машинное обучение» вступительного испытания в магистратуру ИТМО «Искусственный интеллект» (AI
Talent Hub).

Репозиторий содержит разведочный анализ данных, выводы по данным и baseline-модель по датасету, выдаваемому на экзамене.

> **Статус.** Ответы на задание отправлялись через платформу AI Talent Hub. В отведённое время часть C не была
> завершена; она доделана после испытания и опубликована здесь как дополнение к сданной работе:
>
> - [`notebooks/solution.ipynb`](notebooks/solution.ipynb) — решение C1–C5 с кодом, расчётами и сохранёнными
>   выводами (авторитетный источник всех чисел);
> - [`results/C_ANSWERS.md`](results/C_ANSWERS.md) — краткая сводка ответов C1–C5;
> - [`results/submission.csv`](results/submission.csv) — файл предсказаний для C1.

## Задача

Бинарная классификация `relief_granted` — предсказать, закончится ли обращение потребителя компенсацией
(денежной или неденежной), чтобы приоритизировать эскалацию. `complaints_test.csv` — последние месяцы наблюдений,
то есть будущее относительно train, поэтому валидация везде out-of-time.

## Решение и результаты

Данные (`complaints_train.csv` ~7.7 ГБ) обрабатываются out-of-core через **DuckDB**; в pandas/scikit-learn
попадают только уже сокращённые таблицы признаков. Модель — `HistGradientBoostingClassifier` с нативной
поддержкой категорий, out-of-fold target encoding для `Company` и частотным кодированием.

Фактически измеренные метрики на отложенном по времени окне валидации (`2024-12-01 … 2025-04-28`,
1 619 082 обращения, базовая доля позитивов 0.2621):

| метрика | значение |
|---|---|
| PR-AUC (average precision) | 0.4563 |
| ROC-AUC | 0.7612 |
| скользящая валидация, 4 месяца | PR-AUC 0.5072 ± 0.0749 |

Разбор важности признаков, калибровки, порога эскалации, вклада текста жалобы и схлопывания шаблонных обращений
в инциденты — в [`results/C_ANSWERS.md`](results/C_ANSWERS.md) и в ноутбуке.

## Воспроизведение

```powershell
uv sync                 # создать .venv строго по uv.lock
uv run jupyter lab      # запустить ноутбуки интерактивно
uv run ruff check .     # линтер

# полный неинтерактивный прогон решения (перезаписывает выводы в ноутбуке)
uv run jupyter nbconvert --execute --inplace notebooks/solution.ipynb
```

Полный прогон с нуля занимает около 2 часов, из которых ~75 минут — однократное построение кэшей признаков из CSV
(`cache/*.parquet`, не хранится в git). Повторные запуски переиспользуют кэш (~45 минут). Обучающий CSV читается
строго однопоточно (`parallel=false`): внутри значений `Consumer.Complaint.Narrative` встречаются переводы строки,
на которых параллельный CSV-ридер DuckDB завершается ошибкой.

Модель немного нестабильна между прогонами: `HistGradientBoostingClassifier` в многопоточном режиме даёт
неидентичные результаты даже при фиксированном `random_state=42` (порядок суммирования с плавающей точкой).
Ранжирование сохраняется (Spearman 0.998 между двумя прогонами), но отдельные вероятности могут отличаться.
